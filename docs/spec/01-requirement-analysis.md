# 需求分析（Requirement Analysis）

## 1. 原始目标

实现一个规模适中的电子图书馆后端服务，支持用户浏览书籍、查看详情、借阅、归还，以及查看当前活跃借阅。

## 2. 角色

| 角色     | 能力                                     | 本次身份方案                       |
|----------|------------------------------------------|------------------------------------|
| 普通用户 | 浏览书籍、借阅、归还、查看自己的活跃借阅 | `X-User-Id`                        |
| 管理员   | 查看所有用户的活跃借阅                   | `X-User-Id` + `X-User-Role: ADMIN` |

身份请求头是本次作业的最小替代方案，不代表生产级认证设计。生产环境应替换为认证后的主体（authenticated principal）。

## 3. 范围内需求

| 编号          | 需求             | 可验证结果                             |
|---------------|------------------|----------------------------------------|
| REQ-BOOK-001  | 浏览书籍         | 支持分页、关键词和分类查询             |
| REQ-BOOK-002  | 查看书籍详情     | 根据书籍 ID 返回详情，不存在时返回 404 |
| REQ-LOAN-001  | 借阅书籍         | 创建借阅记录并扣减可用授权             |
| REQ-LOAN-002  | 查看当前借阅     | 只返回请求用户自己的活跃借阅           |
| REQ-LOAN-003  | 归还书籍         | 标记归还并恢复授权，不允许越权归还     |
| REQ-ADMIN-001 | 查看所有当前借阅 | 管理员分页查看所有用户的活跃借阅       |

## 4. 关键假设

1. 每本书拥有有限数量的数字授权。
2. `returnedAt == null` 表示借阅仍然活跃；不额外存储可冲突的状态字段。
3. 同一用户对同一本书只能存在一个活跃借阅。
4. 借阅与授权扣减必须原子提交；归还与授权恢复也必须原子提交。
5. 并发请求不承诺 FIFO，先取得书籍行锁的事务先完成逻辑操作。
6. 时间统一使用 UTC；借阅期限由借阅时间加 14 天得到，但当前不执行逾期回收。
7. 不实现认证、书目管理、预约、续借、罚款和数字文件分发。

## 5. 需求歧义的处理

| 原始歧义                 | 采用的解释                                         | 原因                                             |
|--------------------------|----------------------------------------------------|--------------------------------------------------|
| “当前已借阅的书籍”       | 用户侧解释为“我自己的活跃借阅”，另提供只读管理视图 | 同时覆盖用户和运营场景，但不扩大命令面           |
| 是否限制数字内容数量     | 采用有限授权模型                                   | 让借阅具备库存和并发一致性问题，体现领域设计能力 |
| 是否需要完整用户系统     | 不实现，仅使用请求头                               | 题目重点是借阅领域而非认证基础设施               |
| 归还接口是否删除借阅记录 | 保留记录并写入归还时间                             | 保留历史，且便于实现幂等归还                     |

## 6. 非目标（Non-goals）

本次作业不追求完整商业系统。以下内容除非有明确新增需求，否则不应进入实现范围：

- 用户注册、登录、密码和权限持久化；
- 图书目录的增删改；
- 预约、等待列表和 FIFO 分配；
- 逾期任务、罚款、通知；
- 电子书文件、下载授权和内容 CDN；
- 多区域部署、缓存集群和完整运维平台。
